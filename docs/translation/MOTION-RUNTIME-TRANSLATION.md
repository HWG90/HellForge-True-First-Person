# Motion runtime: motion_runtime.lua in C

Translation of retail `src/first_person/motion_runtime.lua` (408 lines, True First Person 0.5.41-smooth.66, kit commit `1d0d453`, SHA-256 `f4435e6b…`): the per-update step that samples locomotion, eases the per-action saved placement, runs the bob / sway model, converts to the rig parent's space, fades over an ADS handoff, softens a pop and submits the result to the owned native pose. The Lua file is the authority. `src/motion_runtime.c` is checked by replaying the retail file's own answers. The recipe is the one of `docs/translation/MOTION-MODULES-TRANSLATION.md` and `docs/translation/POSE-ADAPTER-TRANSLATION.md`.

## Files

| File | What |
| --- | --- |
| `src/motion_runtime.h`, `src/motion_runtime.c` | The translation. Calls `motion_math`, `action_select` and locomotion's `to_parent` directly. |
| `tools/retail_ref/run_motion_runtime.lua` | Loads the retail file unmodified under `/usr/bin/luajit`, with the unmodified retail `motion.lua`, `locomotion.lua` and `action_placement.lua` beneath it, and replays scripts against scripted fakes. |
| `tools/retail_ref/gen_motion_runtime.py` | Writes the scripts, runs them, emits the vectors, measures line coverage. Refuses any retail commit but `1d0d453`. |
| `tests/vectors/motion_runtime_vectors.h` | 49,486 operations in 752 sessions with retail's answers; records the commit and the file's SHA-256. |
| `tests/motion_runtime_test.c`, `tests/run-vectors-motion-runtime.sh` | Replays the vectors against the C. `tests/run-native.sh` picks the script up by its name. |
| `tools/retail_ref/mutate_motion_runtime.py` | The mutation check. |

Regenerate (only when the retail reference is deliberately moved):

    python3 tools/retail_ref/gen_motion_runtime.py --retail "$HOME/Worktrees/goose-gadgets/tfp-smooth/Goose Gadget Kit" --out tests/vectors

Regeneration is byte-identical run to run, and byte-identical between `luajit` and `luajit -joff` (see "x^2" below for the condition).

## Interface

| Retail | C |
| --- | --- |
| `Runtime.new(controller, backend, editor, log, clock, options, dependencies)` | `tfp_motion_runtime_init(rt, host, model_options, &error)`. `model_options` is what `dependencies.motion = Motion.new(options)` was built with; NULL is `Motion.new()`, the shipped case (`runtime.lua:816` passes no dependencies). |
| `self:update()` | `tfp_motion_runtime_update(rt, &reason)` |
| `self:capture_neutral(native_ads)` | `tfp_motion_runtime_capture_neutral(rt, native_ads, &reason)` |
| `self:reset()`, `self:result()` | `tfp_motion_runtime_reset`, `tfp_motion_runtime_result` (a copy of the state, as retail's) |

`TfpMotionRuntime` holds every upvalue of `Runtime.new` under retail's name (`profile_*`, `continuity`, `last_*`, `sent*`, `handoff`, `previous_ads`, `handoff_epoch`, `shown*`, `guard`, `frame_time`, `frame_step`, `state`) and the model (`TfpMotionMath`). No globals.

`TfpMotionRuntimeHost` is the one struct through which everything the Lua object does not own is reached:

| Retail | Host |
| --- | --- |
| `controller.lease`, `backend.alignment_lease`, `backend.placement_weapon_key`, `backend.action_placement_revision or 0` | four fields, read live at the place retail reads them |
| `clock`, `log`, `options` | `clock`, `log` (NULL: none), `options` (NULL: none given, retail's `{enabled=true, scale=1}`) |
| `controller:result()`, `:is_enabled()`, `:get_placement()`, `:set_placement(value)` | `controller_result`, `controller_is_enabled`, `controller_get_placement`, `controller_set_placement` |
| `backend:set_pose_motion(lease, value)`, `:set_ads_placement(lease, ads)`, `:player_snapshot()` | `set_pose_motion`, `set_ads_placement`, `player_snapshot` |
| `backend.action_placement(key, action)`, `backend.action_mapping()`, `backend.presentation_transition()`, `backend.presentation_action(action, now)`, `backend.presentation_resume(identity, player_identity, now)` | the same five names; NULL is "the backend has no such function", which retail tests on every use |
| `editor:is_active()`, `editor.preview_rotation` | `editor_is_active` (NULL: no editor), `editor_preview_rotation` (NULL: the editor has none) |
| `sampler:sample(lease)` (retail: `locomotion.new(backend)`) | `sample`, answering a `TfpLocomotionSample`; in the mod `tfp_locomotion_sample` |
| `dependencies.to_parent` | `to_parent`; NULL (the mod) is `tfp_locomotion_to_parent`. Kept as a seam because retail's own fixture uses it, and three of retail's checks can only be reached through it (see "Proof"). |

Called directly, not through the host: `tfp_motion_math_*` (retail `motion.lua`), `tfp_action_select` (`action_placement.lua`'s `select`), `tfp_locomotion_to_parent`.

The call order into the host is retail's, call for call; the test compares it (see "Proof").

## Carried over from Lua

| Lua | C |
| --- | --- |
| A lease is a table, compared by identity; four upvalues keep it | A lease is a `const TfpMotionRuntimeLease *`, compared by address. Its fields (`done`, `cleanup_only`, `pose_blend_entry`, `origin.identity`, `origin.player_identity`) are read through the pointer at the place retail reads them: `pose_blend_entry` late in the update (`:149`), the old lease's `origin` on the update after the controller left it (`:239-241`). |
| `origin.identity`, `origin.player_identity` (strings) | 64-bit keys with a `has_*` flag (false: not a string), as `transition.h` has them: equal keys, equal strings. |
| `pcall` / `invoke` around a collaborator | The function answers `bool`; false covers "raised" and "answered the wrong type", which retail treats alike at every such place. The text of a raise is the refusal text. |
| A collaborator called without `pcall` (`controller:get_placement()`, `backend.action_placement`, `backend.action_mapping`, `editor:preview_rotation()`, and in `capture_neutral` also `controller:result()` and `:is_enabled()`) | The function answers `TfpMotionRuntimeGot` (nil, value, raised). A raise ends the call with `TFP_MOTION_RUNTIME_RAISED`, with the state as retail leaves it at that point: everything assigned before the raising call is assigned, nothing after. The same answer where retail then indexes a nil (`placement.yaw`, `ads.yaw`, `profile_target[axis]`, `profile_value[axis]`, `result.mode`): `:211`, `:338`, `:352`, `:199`. The order matters and is kept: at `:332-333` the target is stored before the second ADS lookup can raise, at `:343-350` the shared phase is asked and spent before `:352` raises. |
| `a and b or c` with a nil `b` (`:205-206` idle placement, else the controller's; `:332-333` the controller's placement for ADS, else the saved one) | The second call is made when the first answered nil, as retail. |
| `return true`, `return true, reason`, `return false, text` | `TfpMotionRuntimeAnswer` and `*reason` (NULL: nil). After `apply` / `neutral` the reason is always what `report` just stored in `state.reason`. |
| `state` fields that are nil until first written, or nil after a held clock (`speed`, `gait_phase`, `reset`, `rebased`, `sprint_weight`, `sprint_target`, `sprint_held`, `bob_weight`, `shoulder_weight`: `:375` builds an answer without them) | `has_*` flags, `TfpMotionTri`, `TFP_ACT_NONE`. `reset` / `rebased` are `false` or a text: with `has_*`, the enum's NONE is `false`. |
| `previous_ads`, `sent_ads`, `sent_authored`: nil, false or true, compared with `==` | `TfpMotionTri`. nil is not false: a lease's first update with ADS off does not start a handoff, a resumed lease (`sent_lease` set at `:259` with `sent_phase` nil) always submits. |
| `last_options[key] ~= current_options[key]` over eleven keys | Kind and value compared; a value of a wrong type always differs from what was stored (only accepted options are stored). `editor_frozen` and `shoulder_aim_enabled` are not among the eleven, as in retail: a change of only those does not reach the model until another key changes. |
| `model:configure` refusing | `'Invalid motion setting: '` and the setting's name are joined here. |
| `sample.owner` (the `player_identity` string) into the model | The model wants a key. The runtime gives a new key whenever `tfp_same_player` says the sample's player differs from the last sample the model saw. The model only ever compares with the sample before, so this is exact. |
| `x^2` | `x * x`. See "x^2" under open issues. |
| `math.min`, `math.max`, `math.rad` | as `motion_math.c`: the second argument wins on a tie and on NaN; `math.rad(x)` is `x * 1.74532925199432957692e-2`. |
| `t*t*(3-2*t)`, `a+(b-a)*mix`, `1-math.exp(-math.max(0,math.min(dt,.1))/.10)` | written in retail's order; build with `-ffp-contract=off`. |
| `log('FPV motion: '..reason)` only when the reason differs from the last reported one (nil included) | `has_last_message` + text. |
| An assertion of `locomotion.to_parent` reaching `state.reason` and the log through `tostring(parent)` (`:392`) | LuaJIT puts `<chunk>:<line>: ` in front of an assertion's text. C builds `src/first_person/locomotion.lua:<line>: <text>` from the text `tfp_locomotion_to_parent` answers (lines 13, 14, 17, 36, 39, 43, 52, 65, 69), as `pose_adapter.c` does for its own file. The runner cuts the install folder off the chunk name; the line number is compared. A text from the host's `to_parent` is passed on as it is. |

## What C does not express

- **Values of a type the host struct has no room for.** A placement or preview field that is a string or `false`; a sample that is a non-table true value; `sample.ads` as a number (the locomotion sampler answers a boolean: `:110` and `:367` test for a number too, and that half is not in the C); a sample without an owner; a packet without an epoch or with an `ads` that is no boolean; a reason that is no string. None of these comes from the collaborators this repository has.
- **Tables kept by reference.** Retail keeps the table `controller:get_placement()` / `backend.action_placement()` handed it (`profile_value`, `profile_target`), and at `:338` writes the ADS angles into the controller's answer. C keeps copies. Retail's `controller:get_placement()` builds a new table on every call (`controller.lua:102-105`), so the write at `:338` reaches nobody there. A saved placement table edited in place without a revision bump would show in retail and not in C; retail bumps `action_placement_revision` on every save.
- **Three branches no collaborator of this file can reach**, left out: `'Motion options were refused'` (`:277`, the model always gives a text), `'Motion calculation unavailable'` (`:380`, the model always answers a table), and the `not transitioned` half of `:398` (`handoff_parent` always answers its argument).
- **`'Motion module loader unavailable'`** (`:29`): the C links its modules.
- **`dependencies.actions`, a foreign `dependencies.motion`**: the real modules only; the model's options are the one thing passed.
- **A `log` that raises.** Retail does not protect it.
- **Texts longer than 255 characters** are cut (`TFP_MOTION_RUNTIME_TEXT`); retail compares and logs the whole string.

## Proof

- **49,486 operations in 752 sessions**: 47,319 updates, 542 captures, 121 resets, 752 constructions (12 of them refused); 381 operations end in a raised error. Per operation one text is compared, character for character: the call's answer (with its reason text), the ordered trace of every call into a fake with its arguments, and the whole state table. **453,150 host calls** are in the traces (95,288 clock, 47,861 result, 41,083 sample, 32,940 submissions, 12,712 placement writes, 1,081 log lines, …). A number is printed in decimal when it is whole and below 2^31, else as the sixteen hex digits of the double: **521,487 non-whole doubles** are compared by their bits (a NaN must be a NaN).
- The fakes are the same on both sides: about 280 "knobs" (what each collaborator answers, each sample field, each lease's fields, the clock's answer per call) that the script sets before each operation; `run_motion_runtime.lua` and `motion_runtime_test.c` each build their fakes over them.
- Scripts:

## Open issues

- **x^2.** `motion_runtime.lua` squares with `^2` in `vector` (`:20`), `mix_modifier` (`:81`) and `soften` (`:96`); `locomotion.lua` does in `rotation_to_parent` (`:50`, `:58`). LuaJIT's compiled traces compute `x^2` as `x*x`. Its interpreter calls the C library's `pow(x, 2)`, and glibc's `pow` gives the correctly rounded square for about 999 of 1,000 arguments and a neighbour for the rest (measured: 1,716 of 2,000,000 random arguments under `luajit -joff`, none in a compiled loop). Which of the two a given `x^2` gets depends on what the trace compiler has compiled by then, so retail does not have one answer here. The C uses `x*x`, as `locomotion.c` does. To have one definite reference, the generator preloads a small `pow` into LuaJIT that answers `x*x` for an exponent of exactly 2 and the C library's `pow` otherwise (`SQUARE_SHIM` in `gen_motion_runtime.py`; `/usr/bin/luajit` and the retail files are untouched). With it `luajit` and `luajit -joff` give byte-identical answers and the C equals all 49,486. Without it (`--libm-pow`): under plain `luajit` 1 operation differs from the C, under `luajit -joff` 2, each by one unit in the last place of two to four quaternion numbers of one submission (one inside `locomotion.to_parent`'s 120-degree cap, one in `mix_modifier`). In the game the square is whatever the game's Lua and C runtime make of `pow(x, 2)`; this was not measured.
- **`exp`, `acos`, `sqrt`, `cos`** (and the model's and the conversion's own functions): proven with glibc. The Windows runtime's last bit was not run, as for the other motion modules.
- **Lease lifetime.** The runtime keeps a lease's address in `last_lease`, `sent_lease`, `shown_lease`, `profile_lease` and reads `last_lease`'s origin on the first update after the controller left it. Lua keeps the table alive; in C the binder must keep a lease readable until the first `update` / `reset` after it stopped being `controller.lease` has returned, and must not hand the same address to a different lease before then (the runtime would take it for the old one).
- **`'ADS handoff exceeds native bounds'`** (`:398`) is translated but no script reaches it: a normalised blend of two modifiers that each passed `vector` passes it too (retail's own comment at `:76-77` says so). Reaching it needs a not-a-number out of `mix_modifier`, which needs two opposite quaternions, and both ends have `qw >= 0.5`.
- **The chunk name** in front of a conversion refusal is `src/first_person/locomotion.lua` here, the kit-relative name `pose_adapter.h` also uses. What the game's loader names the chunk was not looked at; it shows only in the log line and in `state.reason`.
- **`capture_neutral` is parked** in retail (`runtime.lua:611-613`, only with Fird Person entry) and the shortcut `:297-308` is dead on the shipped path (`backend.action_placement` is always set, `runtime.lua:740`). Both are translated and proven all the same.
- **Options held back.** As in retail, a change of only `editor_frozen` or `shoulder_aim_enabled` in the options does not reach the model (they are not among the eleven compared keys). The shipped options function passes neither.
- This file reads no game memory and has no build constant.
