# Milestone 1, Part B: The camera policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The retail camera helper (`native/first_person/native_ads_camera.cpp` with `camera.lua`), translated to C for build 25480438 and proven equal to the retail C++ by running both on the same game states.

**Architecture:** The helper swaps one function pointer in the engine's CameraAPI table (the position setter) and, on the game's normal camera (request kind 4), replaces the position with the head eye; on the game's own first-person request (kind 6) it forwards the game's frame untouched and only remembers it. Everything it does is listed in `docs/RETAIL-SMOOTH66-INVENTORY.md` section 3, "Camera helper". The retail C++ is compiled natively as a reference through a small Windows shim and its own `NADSC_FIXTURE` seams; a driver feeds the reference and the C translation the same frames on fake memory written in each build's layout (the method of `tools/retail_ref/gen_snapshot.py`) and compares every forwarded position and every counter.

**Tech Stack:** C11; g++ for the reference build of the retail source; the existing fake-memory scenes.

**Spec:** `docs/superpowers/specs/2026-11-16-c-rewrite-design.md`.

## Global Constraints

As in `2026-11-16-m1a-foundation.md`. In addition: the retail C++ sources are compiled from the read-only retail tree at test time and never copied into this repository; a machine without that tree skips the differential tests and says so.

## Review Focus

1. A frame where the game changes the request between the helper's proofs (owner, dispatch slot, graph) and its write: forwarded unchanged, as retail. (Task 3 scenes `changed_between_proofs`.)
2. Memory unreadable on any single read inside the hook: the game's frame is forwarded and the policy disarms only where retail does (errors 3 and 7). (Task 3 `read_fault_at_each_read`.)
3. A weapon swap with no native eye remembered for the incoming weapon: eye hold falls back as retail (fade to head over 80 ms; 150 ms correction when no hold can start). (Task 3 scripts `swap_unknown_weapon`.)
4. Time going backwards or a gap over 250 ms: every carried term resets. (Task 3 `clock_gap`.)
5. Another mod's function already in the CameraAPI slot: refused with API_MISMATCH and reported by name, slot left alone; on removal a foreign value is left alone. (Task 4 `foreign_slot`.)

### Task 1: Pure math (done 2026-11-16)

`src/camera_math.h` translates `free_aim_math.h` (quaternions, `matrix_q`), `camera_correction.h` and `camera_handoff.h`. `tests/diff_camera_math.cpp` runs it against the retail headers on about 3.9 million results, bit for bit. In `tests/run-native.sh`.

### Task 2: Reference build of the retail camera helper (done 2026-11-16)

`tests/winshim/windows.h` and `intrin.h` stand in for the Windows calls the helper uses: memory calls act on this process's real pages (`process_vm_readv`, `mmap`, `mprotect`, `/proc/self/maps` for `VirtualQuery`), locks and events are real, the clock and the hook's caller address are test variables (`shim_clock_ms`, `shim_return_address`). With `NADSC_FIXTURE` defined, `native_ads_camera.cpp` compiles and links natively with g++, unmodified, when the including file has included its standard headers first (libstdc++ uses the name `__try` itself).

Retail's own `camera_fixture.cpp` also compiles, but it cannot run natively: it calls the hook through machine code it writes into its fake game image (a Windows-convention `call` at `game+CALL`), which is how it produces the caller address the hook checks. It stops at its first hooked call (line 182). The differential driver of Task 3 sets `shim_return_address` to `game+CALL+4` for game calls instead. So the retail fixture's 54 groups are not reproduced here; the driver's scripts take their place.

### Task 3: The camera helper (done 2026-11-16)

`src/camera_helper.c|h` (1,267 lines; commit c93005e) is the translation of `native_ads_camera.cpp` behind a host interface; `docs/CAMERA-HELPER-TRANSLATION.md` lists the interface, the 26 build constants with their evidence, what was dropped and what is open. `tests/diff_camera_helper.cpp` (with `_world.h` and `_scripts.h`; commit f305f25) builds the retail source natively and drives both on the same game states written in each build's layout: 192 scripts and 61,073 fault-probe runs, 1.39 million calls, every read, write, swap, lock step and forwarded position compared. No difference was found and no fix to the translation was needed. 187 deliberate single changes to the C: 164 caught, 23 survive and are listed with reasons (unobservable counters, dead statements, unreachable values). Not covered: the Windows build itself and its clock, real concurrency, a hook call before any begin. In `tests/run-native.sh`.
